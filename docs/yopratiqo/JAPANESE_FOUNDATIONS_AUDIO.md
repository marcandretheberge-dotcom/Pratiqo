## Recording coverage

`lib/yo/audio/japaneseFoundationAudio.ts` contains **206 unique recording plans** for **255 visible text forms / 339 pedagogical references** across the eight modules and the synthesis. Coverage includes dialogues, vocabulary, grammar and writing models, roleplay, Yoppo examples, all nine listening stimuli, the forty kanji context words and all ninety-two basic kana.

Hiragana and katakana share recordings when their readings are identical. The kana inventory uses forty-five distinct sounds, including the modern reading of を/ヲ as お. Isolated は and へ retain *ha* and *he*; particles inside sentences follow their contextual readings. The nasal ん needs particular attention during listening review.

Words use authored kana readings as generation input to avoid a different reading of an isolated kanji. Sentences retain their Japanese orthography with kana/rōmaji pronunciation instructions. Displayed course text is unchanged.

Paths are immutable and versioned:

```text
yo/ja/japanese-foundations/v1/japanese-standard/<type>/<slug>.mp3
```

Slugs include a digest of the authored reading. A corrected recording should receive a new version/path so the CDN cannot serve an old object under an unchanged URL.

## Generate and verify

Use the existing repository dependencies. The generation script runs locally or in a trusted server environment; it is not an application route and is never bundled into the browser.

First inspect the offline plan. It requires no secrets, performs no network calls and incurs no API usage:

```sh
npm run generate:yo-japanese-foundations-audio -- --dry-run
```

For generation, provide these variables through the execution environment or the repository's ignored `.env.local`:

```dotenv
NEXT_PUBLIC_SUPABASE_URL=https://jwlbwmxoradmbuvqfkhe.supabase.co
OPENAI_API_KEY=
SUPABASE_SERVICE_ROLE_KEY=
YOPRATIQO_AUDIO_BUCKET=yopratiqo-audio
```

Do not put secret values in source files, browser variables, PR descriptions or command-line arguments. `OPENAI_API_KEY` and `SUPABASE_SERVICE_ROLE_KEY` must remain server-only. The Supabase connector's database access does not supply these execution credentials.

Generate a small first batch, inspect its audio, then continue the same manifest. Existing remote files are skipped; cached generated bytes allow an upload to resume without paying to synthesize the same file again:

```sh
npm run generate:yo-japanese-foundations-audio -- --limit 3
npm run generate:yo-japanese-foundations-audio
```

The manifest filter is exact: these commands select `moduleId: japanese-foundations` and do not generate other courses. Normal uploads do not replace an existing object. The explicit `--force` option is only for an intentional replacement.

`--limit` selects the first N manifest entries, including entries already present; it is not a promise to create N new files. `--force` permits replacement with the same cached generation. To produce different speech, change the recording request and allocate a new immutable path.

Then verify the public files. Verification requires only the public project URL, makes no OpenAI requests and performs no uploads:

```sh
npm run verify:yo-japanese-foundations-audio
```

The generator's resumable cache defaults to `.cache/yopratiqo-audio/` and is ignored by Git. Keep its provenance and hash report until the batch has been checked. A successful run must report every selected item as uploaded/verified or already present and verified, with zero failures. Missing files or rejected generation requests must not be described as completed audio.

The existing Speech API integration uses `POST https://api.openai.com/v1/audio/speech`, `gpt-4o-mini-tts` by default, the Japanese profile's `alloy` voice and MP3 output. Model and voice can be selected with `YOPRATIQO_TTS_MODEL` and `YOPRATIQO_TTS_VOICE`. OpenAI documents the existing Speech API as available until 2027-01-06; the generator will need a separate API migration before that shutdown. Already stored MP3 playback is independent of the generation model.

## Playback and review

The course uses public Supabase URLs, with no runtime generation and no dependency on an installed device voice. Sound starts only after the learner clicks. Controls support stop and 0.78× playback with pitch preservation. Starting another clip, changing the lesson, hiding a panel/tab or unmounting stops the current audio. Only the `playing` event counts as an actual listening start. Missing or interrupted files produce an explicit retry/transcript message.

The listening button keeps a generic accessible label so it does not reveal the answer. Transcript assistance and assessment rules are preserved. The player labels the recordings as AI-generated voices in French, English and Spanish.

Automated tests cover the complete content-to-recording mapping, pronunciation overrides, URL boundaries, cancellation, retries and listening events. They do not establish that a synthesized voice sounds natural. After files exist, check real browser playback and listen to the batch, especially short kana, long vowels, particles, time expressions, prices and sentence endings. Native-speaker pronunciation review remains separate from transport checks.
